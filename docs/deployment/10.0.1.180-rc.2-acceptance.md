## 实际执行和结果

```bash
bash /data/sudostack-ci/38342121745/assets/install-atlas.sh \
  --host 10.0.1.180 --root /data/atlas --manage-k3s
```

首次执行退出码为 0。相同命令再次执行退出码为 0，随后执行：

```bash
/data/atlas/restart.sh
python3 /data/atlas/smoke.py --root /data/atlas --resume
/data/atlas/verify.sh
```

以上命令均成功，验证结果如下：

- Moss、Nexus、SudoWork、PostgreSQL、Caddy 五个 Deployment 均为 1/1 Ready，使用导入后固定 digest 的镜像。
- HTTPS、WebUI 密码登录、WebSocket、gVisor 会话、模拟模型回复和历史保存全部通过。
- 重复安装保留全部五个业务 Pod UID、管理员凭据及 Vault 主密钥。
- 业务重启后五个 Pod 全部重新创建；同一会话能读取此前历史并完成新一轮对话；Vault 主密钥和管理员凭据保持不变。
- 从开发机信任安装 CA 后访问 SudoWork `/health/live` 和 Moss `/readyz`，均返回 HTTP 200。
- 临时模型凭据及测试 Pod/Service/ConfigMap/Secret/NetworkPolicy 全部清理。
- k3s systemd 服务启用；独立 Docker、containerd 和 Moss systemd 服务均未运行。k3s 自带的 containerd 负责 Kubernetes 容器。
